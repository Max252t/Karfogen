# Дизайн нативного окна AI Assistant

Направление — спокойное рабочее приложение: светлый нейтральный фон, мягкие поверхности без лишних рамок,
один акцентный цвет (синий `primary` из темы слайсера), ясная типографика и компактные элементы управления.
Ассистент не наследует устаревшие стили `UM.Theme.styles`, но берёт из темы акцент и семейство шрифта,
поэтому остаётся частью STE Slicer.

## Инструмент проектирования

Figma MCP есть в каталоге коннекторов, но не подключён и требует авторизации аккаунта. Для спокойной ленты
черновой макет карточки выполнения (рабочее состояние и итог) был сделан встроенным инструментом визуализации
сессии (`visualize` → `show_widget`, HTML-макет в чате), а окончательная вёрстка и проверка — в QML на стенде
`scripts/preview_native_ui.py`: он загружает настоящие компоненты с демо-данными и рендерит состояния в PNG для
RU/EN и масштабов 100–200 %. MCP — только инструмент проектирования, в плагин он не попадает.
Ограничение стенда: Qt 5.15 и software-рендер без шейдеров, поэтому иконки там не перекрашиваются
(в слайсере их перекрашивает `UM.RecolorImage`). Окончательная проверка — smoke-тест в STE Slicer.

## Токены (`qml/Style.qml`)

Все размеры задаются в логических пикселях и умножаются на `screenScaleFactor` функцией `Style.px()`.

| Группа | Значения |
| --- | --- |
| Фон и поверхности | окно `#F5F6F8`, поверхность `#FFFFFF`, вторичная `#EEF0F3`, hover `#E6E9ED`, pressed `#DCE0E5` |
| Текст | основной `#1D2329`, вторичный `#56606B`, приглушённый `#7F8994` (только подсказки), отключённый `#9BA3AC` |
| Границы | обычная `#DCE0E5`, усиленная `#C3CAD2` — только у полей и интерактивных карточек |
| Акцент | `primary` темы; hover/pressed — затемнение; мягкий фон — 10 %; кольцо фокуса — 45 % |
| Статусы | успех `#1E7F45`, предупреждение `#9A5B00`, ошибка `#C0362C` — у каждого есть мягкий фон |
| Отступы | 4 / 8 / 12 / 16 / 24 / 32 (`s1`…`s6`) |
| Радиусы | 6 мелкие, 8 кнопки и поля, 12 крупные поверхности |
| Высоты | 28 компактные, 32 обычные, 36 крупные элементы |
| Шрифт | семейство из темы (Roboto, кириллица), 11 / 12 / 13 / 14 (чтение) / 15 / 19 / 20 (показатели) |

Состояния: hover — светлее/темнее фон, pressed — следующая ступень, focus — кольцо 2 px акцентного цвета,
disabled — вторичная поверхность и приглушённый, но читаемый текст. Статус никогда не передаётся только цветом:
у него всегда есть иконка и подпись.

## Компоненты

`AButton` (primary, secondary, ghost, accent, danger, link; small/normal/large; иконка; режим «только иконка»),
`IconButton`, `Field`, `CheckRow`, `Segmented`, `Pill`, `ContextChip`, `Card`, `Disclosure`, `SectionTitle`,
`KeyValue`, `Toast`, `Spinner`, `Icon`, компоненты спокойной ленты (`ActivityCard`, `ProgressLine`, `StageList`,
`DecisionTable`, `ParamChanges`, `MetricsRow`, `FileList`, `PathText`, `TechBlock`, `RichBlocks`, `DataTable`,
`AnswerView`) и набор линейных SVG-иконок `qml/icons` (одна толщина штриха).

Подсказки показывает `HoverTip` через собственную `MouseArea` кнопки. Раньше поверх кнопок лежала
`UM.TooltipArea` — вторая `MouseArea` с наведением, которая перехватывала курсор, и над карандашом и крестиком
в проектах оставалась стрелка. Все кликабельные элементы теперь показывают курсор-руку.

## Ключевые UX-решения

- **Шапка.** Название проекта — кнопка, ведущая к списку проектов (полное имя в подсказке). Справа компактный
  индикатор подключения: точка и короткое слово; модель и подробности — в подсказке, по клику — настройки.
  Ошибка подключения подсвечивается мягким красным фоном индикатора, а не баннером.
- **Навигация.** Три лёгкие вкладки с мягкой подсветкой активной; счётчики вторичны.
- **Лента.** Колонка ограничена 720 логическими пикселями для удобной длины строки. Сообщение пользователя —
  мягкая заливка, ответ ассистента — обычный текст, весь текст выделяется и копируется. Работа агента —
  одна карточка выполнения на запрос (см. «Спокойная лента»); JSON только в раскрытых подробностях.
  Ошибки — мягкая красная карточка с объяснением, влиянием на результат и действиями.
  Если пользователь листает историю, автопрокрутка не мешает, а внизу появляется «Новые сообщения».
- **Поле ввода.** Единый блок: контекст запроса (модель из сцены и вложения карточками с превью), текст,
  скрепка, выбор режима и отправка. Модель из сцены выбирается одним кликом, выбранная карточка подсвечена
  и отмечена галочкой. При прикреплении файлов появляется уведомление «Прикреплено…».
  Во время работы кнопка отправки меняется на «Остановить», над полем объяснено, почему нельзя отправить.
  В узком окне выбор режима переносится на отдельную строку, кнопка отправки сжимается до иконки.
- **Режим.** «Авто» по умолчанию; выбор в поле ввода — намерение пользователя. На вкладке «Результат» режим
  показан как применённое состояние с пометкой «выбран ассистентом» или «задан вами».
- **Результат.** Сверху статус («Результат готов», «Идёт слайсинг», «Модель ещё не нарезана», «Результат из истории
  проекта») и три крупных показателя. Файлы — отдельный блок. Решения, изменения и история — раскрывающиеся
  разделы. Сброс настроек вынесен в отдельный блок с объяснением последствий и подтверждением.
  Изменения, которые не меняют значение (3D → 3D) или вернулись к исходному, не показываются.
- **G-code.** Готовность берётся из реального состояния слайсера: монитор подключается к бэкенду при старте,
  поэтому G-code сохраняется и после нарезки штатной кнопкой слайсера, а не только после слайсинга агентом.
  Результат из истории проекта не выдаётся за актуальный: кнопка сохранения G-code активна только для текущей
  нарезанной сцены.
- **Проекты.** Строки без рамок, текущий проект отмечен мягким фоном и меткой «Открыт», действия
  переименования и удаления — тихие иконки, проявляющиеся при наведении.
- **Настройки.** Группы «Подключение», «Поведение ассистента», «Результаты», «Язык»; обязательные поля помечены
  звёздочкой; у проверки подключения три явных состояния — ожидание, успех, ошибка. Ключ не показывается даже маской.
- **Уведомления.** Тип (успех, предупреждение, ошибка, информация) с иконкой; появляются над полем ввода,
  не перекрывают его, держатся 6–9 секунд и не исчезают, пока на них наведён курсор.

## Спокойная лента

Цель — чтобы пользователь с одного взгляда понимал, что ассистент делает сейчас, что уже готово, чем закончился
этап и где результат, а технические подробности не мешали читать переписку.

### Три уровня раскрытия

| Уровень | Что видно | Где |
| --- | --- | --- |
| 1. Короткий статус | этап, примерный процент, шкала, живой статус | карточка выполнения, всегда |
| 2. Итог этапа | одна строка: «✓ Модель проанализирована · 62 × 40 × 35 мм» | «Что уже сделано» / «Ход работы» |
| 3. Подробности | факты этапа (габариты, объём, изменения), затем «Технические подробности» с JSON | по клику |

Данные и ошибки не удаляются ради краткости: меняется только способ показа. Сырые аргументы и ответы
инструментов, промежуточные реплики модели и первая ошибка исправленного вызова живут в подробностях этапа.

### Что остаётся в ленте

Сообщение пользователя → одна карточка выполнения на запрос → короткий ответ ассистента → карточка ошибки,
если нужно действие. Вызовы инструментов, статусы и промежуточный текст отдельными сообщениями не показываются.
Запрос без единого инструмента (обычный вопрос) карточку не показывает вовсе.

### Карточка выполнения (`ActivityCard`)

- **Работа:** спиннер, название этапа («Настраиваю печать»), справа «≈ 64 %» с подсказкой «Примерный прогресс
  по выполненным этапам», тонкая шкала с плавной анимацией ширины, приглушённый живой статус с иконкой,
  внизу «Что уже сделано · 4 этапа». Единственная кнопка «Остановить» находится в поле ввода; на других
  вкладках она переносится в полосу выполнения. Пока стадию определить нельзя — бегущая полоска
  без процента и «Оцениваю задачу».
- **Готово:** «✓ Подготовка завершена», строка «3D · Generic PETG · normal», крупные показатели
  (время, филамент, материал), «Посмотреть результат» и «Подробнее». «Подробнее» раскрывает решения,
  изменения параметров, файлы и ход работы.
- **Ошибка:** «Работа прервана», шкала красная и остаётся на достигнутом проценте, строка «Выполнено примерно
  45 % работы, уже сделанные изменения сохранены». Отдельная карточка ошибки объясняет, что делать.
- **Остановлено:** серая шкала на достигнутом проценте, «Остановлено» и кнопка «Продолжить».

### Структурированные компоненты

| Компонент | Назначение |
| --- | --- |
| `ProgressLine` | шкала: значение, неопределённый режим, тон accent / danger / muted |
| `StageList` | история этапов: иконка состояния, итог одной строкой, факты, технические подробности |
| `KeyValue` | ключ–значение (факты этапа, настройки на вкладке «Результат») |
| `DecisionTable` | «Принятые решения»: значение и «Почему»; на узкой ширине — вертикальные карточки |
| `ParamChanges` | «Параметры печати · 6 изменений»: «2 → 4», старое приглушено, технический ключ — в подсказке |
| `MetricsRow` | крупные показатели слайсинга с подписями |
| `FileList`, `PathText` | файлы экспорта, путь с сокращением посередине, копирование, «Открыть папку» |
| `TechBlock` | моноширинный текст на мягком фоне, перенос строк, копирование, ограниченная высота с прокруткой |
| `RichBlocks`, `DataTable` | безопасный Markdown: заголовки, абзацы, списки, выделение, `code`, ссылки, таблицы, блоки кода |
| `AnswerView` | ответ ассистента со сворачиванием длинного текста |

Одинаковые старое и новое значения не показываются. Числа форматируются единообразно (в русском —
десятичная запятая, без хвостов вроде `0.15000000000000002`), `True/False` — «Вкл./Выкл.». Длинные значения
переносятся; горизонтальной прокрутки у обычных параметров нет.

### Длинные ответы

Ответ длиннее ~480 символов или 9 строк показывается началом высотой ~170 px с мягким градиентом и кнопками
«Читать полностью» / «Свернуть» и «Копировать текст». Никогда не сворачиваются ответы с вопросом в последнем
абзаце (агенту нужен ответ) и с предупреждениями («внимание», «опасно», «warning», «⚠»…). Ошибки — отдельные
карточки, они не сворачиваются. Полный текст хранится в модели (`plain`) и копируется целиком.

### Живые статусы

Короткая приглушённая строка внутри карточки описывает наблюдаемую активность: «Осматриваю модель со всех
сторон…», «Слайсер считает траектории. Самая математическая часть.» Это не сообщения ассистента и не
рассуждения модели: фразы выбираются локально по текущему этапу (`ui/live_status.py`), без запросов к LLM,
не попадают в историю LLM, в события шины и в файл проекта. Фраза меняется не чаще раза в 6–10 секунд и не
повторяется подряд; шутливые фразы редкие (не две подряд, не чаще одной из трёх смен). При ошибке этапа
шутки прекращаются, при ошибке, отмене и завершении строка исчезает. Настройка «Живые статусы» включена
по умолчанию. Поддержаны русский и английский.

### Анимации

Плавное изменение ширины шкалы (320 мс), бегущая полоска только в неопределённом режиме, короткое раскрытие
длинного ответа (140 мс), спиннер текущего этапа. Постоянных декоративных движений нет. Все длительности
берутся из `Style` (`progressMs`, `revealMs`, `motion`): один переключатель отключает анимации.

## Язык, названия и стыковка

- Язык интерфейса и ответов модели один и тот же; режим «Авто» показывает, какой язык он сейчас выбрал.
- Пока задача не ясна, проект называется «Новый проект»; приветствия не становятся названием.
- Окно ассистента стыкуется справа от слайсера и занимает около 25 % экрана, слайсер остаётся слева и не
  перекрывается. Подробности — в `docs/native_ui.md`.

## Ограничения

- В дистрибутиве одна светлая тема, поэтому тёмная версия окна не делалась.
- `QtQuick.Controls.Private 1.0` используется только для нативной всплывающей подсказки — так же, как его
  использует `UM.TooltipArea` в самом слайсере.
- Межстрочный интервал у выделяемого текста (`TextEdit` с RichText) задаётся Qt и не настраивается в Qt 5.10;
  абзацы разделяются пустой строкой.
- Высота окна настроек ограничивается экраном; на маленьких экранах содержимое прокручивается.
- Состояние раскрытия («Подробнее», этапы) хранится в делегате ленты: если карточка уходит далеко за
  пределы экрана и делегат пересоздаётся, она снова показывается свёрнутой.
- В Qt 5.10 нет системного признака «уменьшить движение», поэтому анимации отключаются флагом `Style.motion`.
