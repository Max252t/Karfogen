# Архитектура AI Assistant

Плагин встраивает в STE Slicer чат-бота. Пользователь описывает задачу печати, прикладывает модель или фото,
а LLM управляет слайсером через инструменты. Выбор режима, материала, профиля и настроек делают правила в коде,
LLM интерпретирует запрос, вызывает инструменты и объясняет решения.

## Стек и ограничения

- Python 3.5 (встроен в слайсер), только стандартная библиотека и модули дистрибутива (`UM`, `steslicer`, PyQt5, numpy).
  Сторонние пакеты поставить нельзя, поэтому MCP, HTTP-клиент LLM и HTTP-сервер написаны вручную.
- Qt 5.10 и QML с ограниченным набором импортов (см. `docs/native_ui.md`).
- Запросы к LLM — OpenAI-совместимый Chat Completions с вызовом инструментов, через `urllib`.
- Интерфейс — нативное QML-окно внутри слайсера. Браузерная страница (`web/`) оставлена как legacy.

## Схема

```
QML-окно (qml/*.qml)
   │ pyqtSlot / pyqtProperty / модели списков
NativeChatController (ui/controller.py, QObject, главный поток)
   │ читает EventBus каждые 150 мс          ▲ события
   ▼                                        │
ChatViewState (ui/view_state.py)     EventBus (server/events.py)
                                            ▲
   ┌────────────────────────────────────────┤
Agent (agent/agent.py, фоновый поток)       │
   ├── LLM по HTTPS (agent/llm_client.py)   │
   └── tools/call ──► реестр инструментов ──┘ события tool_call, tool_result, ...
                          │
                          └── run_on_main ──► API слайсера (сцена, настройки, слайсинг)

Внешний MCP-клиент ──POST /mcp──► HTTP-сервер (server/http_server.py) ──► тот же обработчик tools/call
```

Нативное окно с HTTP-сервером не общается: оно использует агент, шину событий и менеджер проектов напрямую.
Сервер нужен ради `/mcp` для внешних клиентов (и устаревших `/api/*` для legacy-страницы).

## Модули (`plugin/AIAssistant`)

| Путь | Назначение |
|---|---|
| `__init__.py`, `plugin.json`, `AIAssistant.py` | Регистрация расширения, меню Extensions → AI Assistant → Open chat, создание окна, запуск MCP-сервера, корректное завершение |
| `config.py` | Настройки в preferences слайсера, переменные окружения, язык слайсера (`general/language`), папка результатов |
| `mcp/registry.py` | Единый реестр инструментов: имя, описание, схема аргументов, проверка типов; выдача списка для MCP и для LLM |
| `mcp/protocol.py` | JSON-RPC 2.0: `initialize`, `ping`, `tools/list`, `tools/call`; ошибка инструмента возвращается как `isError`; публикует события вызова |
| `server/http_server.py` | Локальный HTTP-сервер только на `127.0.0.1`; `/mcp`, `/api/*` (legacy), проверка `Host` и `Origin` |
| `server/events.py` | Очередь последних 1000 событий со счётчиком `revision` для перестроения ленты при смене проекта |
| `server/derived_events.py` | Из результатов инструментов строит события для панелей: изменённые параметры, сцена, итоги слайсинга, таблица решений |
| `server/projects.py` | Хранилище проектов на диске, менеджер текущего проекта, автосохранение, потокобезопасная атомарная запись |
| `server/uploads.py` | Приём вложений (jpg, png, stl, obj, 3mf до 100 МБ); изображения уменьшаются и перекодируются через Qt |
| `agent/agent.py` | Цикл диалога, лимит шагов, остановка, сжатие истории, повтор без картинок при отказе модели |
| `agent/llm_client.py` | Запросы к LLM, повторы, понятные ошибки, доверенные сертификаты |
| `agent/prompts.py` | Системный промпт на выбранном языке |
| `agent/knowledge.py` | Правила: режим 3D/5D, рейтинг материалов, профиль и настройки; тексты причин RU/EN |
| `tools/main_thread.py` | `run_on_main`: выполнение в главном потоке слайсера с таймаутом и отменой |
| `tools/settings_tools.py` | Принтер, режим печати, материалы, профили, поиск и запись настроек. Всего в плагине 35 инструментов |
| `tools/scene_tools.py` | Загрузка модели, анализ, ориентация, перемещение, масштаб, расстановка |
| `tools/geometry.py` | Геометрия на numpy: объём, нависания, площадь основания, кандидаты ориентации, ось симметрии |
| `tools/slice_tools.py` | Слайсинг, статус, результат, экспорт G-code и 3MF, слежение за слайсингом из интерфейса слайсера |
| `tools/advisor_tools.py` | `recommend_setup`: применяет правила базы знаний к модели |
| `ui/controller.py` | `QObject` для QML: свойства, слоты, модели списков, опрос шины событий, проекты, экспорт |
| `ui/view_state.py` | Чистая логика без Qt: превращает события в ленту, параметры, решения, состояние слайсинга |
| `ui/strings.py` | Строки интерфейса, названия инструментов и тексты ошибок RU/EN |
| `qml/` | QML-окно и компоненты (`AssistantWindow.qml`, страницы чата, результата, проектов, диалоги, иконки) |
| `web/` | Legacy-страница браузера, из слайсера не открывается |
| `certs/` | Корневой сертификат GlobalSign Root R46 для проверки HTTPS LLM-провайдера |

## Работа сценария

1. Пользователь пишет запрос (при необходимости прикрепляет файлы или берёт модель из сцены). Первое сообщение создаёт проект.
2. Агент отправляет историю и список инструментов в LLM. Системный промпт содержит порядок работы и правила базы знаний.
3. Каждый вызов инструмента проходит через `protocol.call_tool`: публикуются события `tool_call` и `tool_result`, интерфейс показывает карточку действия, а `derived_events` обновляют панели.
4. Типичная цепочка: `load_model` → `analyze_mesh` → `recommend_setup` → доработка настроек → `slice` → при автоэкспорте `export_gcode` и `save_project_3mf` → объяснение решений.
5. `recommend_setup` по геометрии и тегам задачи выбирает режим (3D/5D), материал из доступных на принтере, профиль качества и ключевые настройки, ориентирует деталь и применяет всё.
6. После ответа и по ходу работы (раз в 5 секунд) переписка и события сохраняются на диск в `<results>/_projects/<id>/project.json`.

## Правила подбора (`agent/knowledge.py`)

Это гипотезы, выведенные из семи тестовых деталей; их нужно подтвердить экспертами.

- **Режим.** 5D для тел вращения с отношением длина/диаметр от 0,35 и средней стенкой от 2,5 мм при требованиях точности,
  вращения, износа, нагрузки или герметичности; для валов с призматическим профилем. Эластичные, декоративные детали,
  прототипы и плоские диски остаются в 3D. Режим 5D Spiral правила не выбирают.
- **Материал.** Рейтинг по свойствам (температура, жёсткость, износ, УФ, химия, влажность) и температуре эксплуатации.
  Затем тип сопоставляется с реально доступным материалом (`enduse_*` для функциональных деталей, `generic_*_175`).
  Спецсемейства (`fiberpart_`, `contifiber`, `metalcast_`, `proto_`) без прямой просьбы не выбираются.
  Для эластичных деталей (`flexibility=flexible`: пыльники, уплотнения, прокладки) берётся мягкий TPU для уплотнений
  (`sealant_tpu93`, `sealant_tpu`, `sealant_tpu_A95`), а не Enduse TPU D70 (Шор 70D); для жёстких деталей `sealant_*` не выбираются.
- **Настройки.** Под нагрузку: 4 периметра, заполнение 40% gyroid, 6 верхних и нижних слоёв. Декор: тонкий слой, 2 периметра, 10%.
  Прототип: слой 0,2 мм. Гибкие детали: пониженная скорость, поддержки выключены (из того же материала они спекаются с деталью);
  у тонкостенных эластичных оболочек заполнение не меняется, потому что стенку целиком заполняют периметры.

## Потоки и безопасность

- Любое обращение к сцене, настройкам и бэкенду выполняется только в главном потоке через `run_on_main`.
  Исключения: запись G-code и 3MF идёт из рабочего потока (записывающие модули слайсера сами переходят в главный; вызов из него блокирует слайсер),
  а контроллер QML изменяет модели только в главном потоке.
- Длительные операции (LLM, инструменты, экспорт, проверка подключения) работают в фоновых потоках.
- Ассистенту запрещено менять настройки принтера и G-code, `create_profile` ему не выдаётся.
- HTTP-сервер слушает только `127.0.0.1`, отклоняет чужой `Origin`/`Host`. Ключ API хранится в настройках слайсера
  и показывается только маской; в репозитории ни ключей, ни адресов нет.

## Проекты и состояние

- В проект сохраняются переписка, события и история для LLM. Сцена слайсера не сохраняется: открытие проекта возвращает переписку.
- Новый проект предлагает очистить сцену и сбросить пользовательские изменения настроек, чтобы настройки прошлой детали не переходили в новую.
- Пока ассистент работает, можно просматривать текущий проект, но нельзя переключаться на другой или менять папку результатов.
