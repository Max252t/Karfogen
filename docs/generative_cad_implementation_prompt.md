# Промт на реализацию генерации моделей для 3D-печати

Ниже приведён готовый промт для coding-агента, который должен реализовать функциональность в репозитории Karfogen.

```text
Ты работаешь в репозитории Karfogen — плагине AI Assistant для STE Slicer. Реализуй возможность создавать
готовую к печати 3D-модель по текстовому запросу пользователя, даже если исходный STL/3MF не приложен.

Пример целевого сценария:

1. Пользователь пишет: «Сделай болт».
2. Ассистент понимает, что для построения не хватает критичных размеров, и задаёт один компактный набор
   уточняющих вопросов: стандарт/тип резьбы, диаметр, шаг, длина, тип головки, назначение и требуемый посадочный
   зазор. Вопросы, для которых допустим безопасный распространённый вариант, сопровождаются предлагаемым
   значением по умолчанию.
3. После ответа ассистент создаёт параметрическую модель, добавляет её в сцену, проверяет сетку и размеры,
   показывает пользователю принятые параметры.
4. Затем выполняется существующий процесс: анализ модели, подбор материала/режима/профиля, проверка рабочего
   объёма, слайсинг и экспорт 3MF/G-code в соответствии с настройками приложения.
5. Пользователь может написать «сделай на 10 мм длиннее» или «замени головку на потайную» — модель должна быть
   перестроена из сохранённых параметров, а не создаваться заново по догадке.

Перед изменениями полностью изучи текущую архитектуру, существующие инструменты, формат событий, хранение
проектов, ограничения Python 3.5 и тестовые соглашения. Сохрани обратную совместимость и не ломай сценарий,
в котором пользователь прикладывает готовую модель.

## Границы первой версии

Первая версия не должна обещать генерацию любой произвольной механической детали. Реализуй надёжный
параметрический MVP со следующими типами:

- болт;
- гайка;
- шайба;
- прямоугольная пластина с настраиваемыми отверстиями;
- простой угловой кронштейн.

Архитектура должна позволять добавлять новые генераторы без изменения общего протокола инструмента.
Для неизвестной или слишком сложной детали ассистент должен честно сообщить об ограничении и предложить:
упрощённую поддерживаемую форму, загрузку готовой модели либо подготовку точного технического задания.

## Инструменты агента

Добавь инструменты с JSON-схемами, строгой валидацией и понятными ошибками:

1. `list_generatable_parts` — возвращает поддерживаемые типы деталей, доступные параметры, единицы измерения,
   допустимые диапазоны и значения по умолчанию.
2. `create_parametric_model` — создаёт новую модель по `part_type` и объекту `parameters`, сохраняет исходную
   параметрическую спецификацию и загружает результат в сцену. Возвращает как минимум идентификатор объекта,
   фактические параметры, габариты, путь к геометрическому файлу и предупреждения.
3. `update_parametric_model` — изменяет только переданные параметры ранее созданной модели, перестраивает её,
   заменяет объект в сцене без появления дубликатов и возвращает те же данные, что создание.
4. `validate_generated_model` — проверяет замкнутость/многообразность сетки, вырожденные треугольники,
   нормали, минимальную толщину, габариты и попадание в рабочий объём. Ошибки, препятствующие печати,
   должны отличаться от предупреждений.
5. Если существующие инструменты сохранения не позволяют экспортировать геометрию отдельно, добавь
   `export_generated_model` для STL и, если реально поддерживается стеком приложения, 3MF. Не заявляй формат,
   который фактически не создаётся.

Не разрешай LLM передавать программный код, скрипты, выражения или произвольные пути для выполнения.
Инструмент принимает только типизированные параметры из белого списка. Любая генерация выполняется локальным
доверенным кодом плагина. Имена файлов очищаются, а запись разрешена только в настроенной папке результатов.

## Геометрия и печатные допуски

- Используй миллиметры во всех публичных параметрах и результатах.
- Модель должна быть детерминированной: одинаковая спецификация создаёт одинаковую геометрию.
- Сетка должна быть замкнутой, с согласованными наружными нормалями и без вырожденных граней.
- Не имитируй настоящую резьбу простой текстурой. Поддержи явный параметр `thread_mode`: `modeled` для
  геометрической печатаемой резьбы и `cosmetic` только для непечатаемого визуального обозначения. Перед
  слайсингом косметическая резьба должна быть запрещена либо явно заменена гладким цилиндром с предупреждением.
- Для метрического крепежа поддержи как минимум правую наружную/внутреннюю ISO-совместимую геометрию в
  пределах разумных для MVP размеров. Стандартные шаги не придумывай: храни их в проверяемой таблице.
- Разделяй номинальные размеры и печатную компенсацию. Добавь явные параметры зазора/компенсации и возвращай
  их пользователю. Не гарантируй посадку без калибровки конкретного принтера.
- Ограничь детализацию резьбы и число сегментов так, чтобы модель не блокировала интерфейс и не создавала
  чрезмерно большой файл. Длительную генерацию выполняй вне главного UI-потока; работу со сценой оставь через
  существующий механизм главного потока.
- Для силового крепежа всегда возвращай предупреждение: печатная пластиковая деталь не считается заменой
  сертифицированного металлического крепежа без инженерного расчёта и испытаний.

## Диалоговое поведение

Расширь системный промпт агента. Если пользователь просит создать деталь и не прикладывает модель:

- сначала вызови `list_generatable_parts`, если схема параметров ещё не известна в текущем диалоге;
- отдели критичные параметры от необязательных;
- не вызывай генерацию, пока отсутствуют параметры, без которых результат может принципиально не совпасть
  с назначением детали;
- задай один сгруппированный, короткий вопрос вместо длинной серии сообщений;
- рядом с вопросом предложи безопасные значения по умолчанию, но не подставляй критичные размеры молча;
- если пользователь явно разрешил выбрать параметры самостоятельно, используй распространённый печатаемый
  вариант, перечисли все допущения до генерации и дай возможность исправить их;
- после генерации обязательно вызови `validate_generated_model`;
- при ошибке валидации не переходи к слайсингу; исправь допустимый параметр или объясни, что нужно изменить;
- после успешной проверки используй существующий процесс `analyze_mesh` → `recommend_setup` → проверка
  габаритов → `slice` → экспорт;
- для изменения ранее созданной детали используй `update_parametric_model`, сохраняя неизменённые параметры;
- в финальном ответе кратко укажи тип детали, основные номинальные размеры, применённые компенсации,
  результат проверки и готовность файлов. Не утверждай, что модель готова, если инструмент этого не подтвердил.

Для запроса «Сделай болт» предпочтительный первый ответ должен быть примерно таким по смыслу:

«Уточните параметры болта: размер резьбы и шаг (например, M8×1,25), длину стержня, тип головки
(шестигранная/цилиндрическая/потайная) и назначение. Если специальных требований нет, могу подготовить
тестовый M8×1,25 длиной 30 мм с шестигранной головкой и печатной компенсацией под ваш принтер.»

Не копируй пример дословно в код: поведение должно строиться на схеме параметров инструмента и языке
текущего пользователя. Сохрани существующие языковые контракты RU/EN.

## Хранение состояния и интерфейс

- Сохраняй параметрическую спецификацию вместе с проектом: версия схемы, тип детали, параметры, единицы,
  идентификатор объекта, путь результата и отметка времени.
- Старые проекты без такой секции должны открываться без миграционной ошибки.
- Добавь в события данные, достаточные для отображения карточки «Созданная модель»: тип, параметры, габариты,
  статус проверки и предупреждения.
- Используй существующий стиль интерфейса. Не создавай отдельный браузерный интерфейс.
- При повторном открытии проекта пользователь должен видеть спецификацию. Если сцена не восстанавливается
  текущей архитектурой, явно предложи перестроить модель из сохранённой спецификации.

## Реализация

Предпочти встроенные возможности и уже доступные зависимости STE Slicer. Нельзя добавлять обязательную
системную зависимость, не входящую в поставку, и нельзя нарушать совместимость с Python 3.5. Если полноценная
резьба невозможна средствами текущего окружения, сначала зафиксируй техническое ограничение и реализуй
наименьший честный вариант, который всё равно создаёт реальную проверяемую сетку; не подменяй генерацию
текстовым ответом.

Вынеси генераторы, схемы параметров и проверки в отдельные модули с чистой логикой, чтобы большая часть
тестов выполнялась без запуска Qt и слайсера. Не смешивай математическое построение сетки с UI, HTTP или LLM.
Все ошибки инструментов должны быть понятны пользователю и содержать поле/параметр, который нужно исправить.

## Проверки и критерии приёмки

Добавь автоматические тесты как минимум на следующие случаи:

- список поддерживаемых деталей и их схем;
- создание каждого типа детали с валидными параметрами;
- отклонение неизвестного типа, отсутствующего критичного параметра, строки вместо числа, NaN/Infinity,
  отрицательного размера и значения вне диапазона;
- болт с типичным метрическим размером: ожидаемые габариты, замкнутая сетка, наружные нормали и отсутствие
  вырожденных треугольников;
- гайка, совместимая по номиналу с болтом, с отдельно применённым зазором;
- обновление длины без потери остальных параметров и без дубликата объекта;
- сохранение/загрузка спецификации и открытие старого проекта без неё;
- корректная публикация событий и регистрация OpenAI/MCP-инструментов;
- запрет произвольного пути и исполняемого содержимого;
- русское и английское поведение системного промпта;
- сохранение существующего сценария загрузки STL и полный существующий набор тестов.

Проведи доступные проверки проекта, включая тесты, проверку Python 3.5 и гигиену репозитория. Если среда не
позволяет выполнить интеграционный тест со слайсером, явно укажи это в итогах, но полностью протестируй чистую
геометрию, протокол и сохранение состояния.

Готовность считается достигнутой, когда запрос поддерживаемой детали без вложения приводит через уточнение
параметров к реальному валидному объекту в сцене, объект можно изменить последующей фразой, нарезать и
сохранить штатным процессом. Одного изменения системного промпта без инструментов генерации недостаточно.

В конце предоставь краткий отчёт: что реализовано, какие файлы изменены, какие ограничения остались и какие
проверки прошли. Не коммить и не публикуй изменения, если это не было отдельно запрошено.
```
